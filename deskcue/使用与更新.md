# DeskCue 使用与更新

当前公开版本为 1.5.9.3，已完成本地 x64 及云端 x64/ARM64 构建、测试及发布；隔离环境中
检查更新、托盘右键和正常退出已通过。完整证据、恢复记录及审阅状态见
[HANDOFF.md](../docs/HANDOFF.md)。早前一次托盘失灵原因尚未定位，不能据这次
成功复测宣称已修复所有偶发故障。

## 日常使用

本机可以从项目的“发布版”目录打开 DeskCue.exe；运行时保留这个完整目录。

从 [本项目 Releases](https://github.com/CyberShadowX/DeskCue/releases) 下载适合
电脑架构的 `DeskCue_Setup_<版本>_x64.exe` 或 `..._arm64.exe` 并运行安装。
这些是带私有运行时的完整离线安装包，不需要另外安装 .NET。

在软件设置的更新区域点击“检查更新”。只有本仓库已完成测试、构建和校验的
DeskCue 安装包才是可安装更新；不会下载原版 DeskBox 安装器。检查/下载与
实际安装各自保留原版交互。公开更新无需 GitHub 凭据，应用中不保存仓库写入令牌。

待办、随记、布局与设置保存在本机，不因公开源码而上传。旧 WPF DeskCue 的
数据库和设置已私下归档，未自动导入本版本。文件格子的整理/移动/删除仍以
用户在软件中的明确操作为准。

## 云端自动跟进

仓库 Actions 中的 `DeskCue stable upstream delivery` 每六小时检查上游正式版，
也可手动点击 Run workflow。无新版本时仅检查；有新版本才准备独立候选源码，
重放 DeskCue 改名与补丁，通过双架构验证后发布。电脑关机不影响云端运行。

已验证实际定时触发成功，见[定时检查记录](https://github.com/CyberShadowX/DeskCue/actions/runs/40639466001)。
当时没有待跟进的正式版，因此构建和发布按设计跳过。

新上游版本与可安装的 DeskCue 更新不是同一时间产生，需要等待云端构建。
补丁冲突、测试/下载/校验失败会阻止交付。失败后保持现有可用版本，并保留
冻结候选与上传证据用于重试；不会偷偷切回原版，也不会自动在你的电脑编译。

日常不需要手动 Sync fork。若工作流报告冲突或长时间没有更新，可把具体
Actions 运行链接交给 Codex 诊断。GitHub 可能停用长期无仓库活动的定时工作流，
需要在 Actions 中重新启用；自动跟进不等于永久零维护。

如果上游新增或修改了 GitHub 工作流，GitHub 还可能拒绝机器人推进这些文件。
这会停止本次交付，保留原版本；需要先审核并同步相应工作流，再重试。不要为
绕过这类阻断而把仓库写入令牌放进软件。

## 本地备用

在可信、干净的 DeskCue 源码目录中运行：

```powershell
pwsh -NoProfile -File .\tools\Publish-DeskCue.ps1 -Platform x64
```

本地与云端使用同一套源码、版本、改名、补丁、测试及打包规则。需要
.NET SDK10.0.402、Rust1.96.0、对应 MSVC/Windows SDK 和 Inno Setup6。
本机已准备的便携工具位于 `F:\AI\AIProjects\.deskcue-tools`；没有修改全局 PATH。
本机 ARM64 构建还需要相应的 VS ARM64 C++ 工具；不能以 x64 成功代替 ARM64。

若需直接验证新的上游稳定版本，使用 `deskcue/Sync-DeskCue.ps1` 的明确版本与
独立目标目录准备候选，再对候选执行共享构建。此命令只准备源码，不直接
覆盖正在使用的程序、推进远程 main 或安装更新；普通用户可交给 Codex 完成。

本地发布入口会生成完整运行目录与安装器并保留旧发布目录。目标程序正在运行
时保持替换阻断，先从系统托盘正常退出后重试。脚本不强杀、不自动安装或启动。
